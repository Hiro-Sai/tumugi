7. （1段目からの続き）ライセンスは付けず「閲覧用・無断での利用・改変・再配布はお断り」と書く。名前は出さず、ハンドルネーム「Hiro-Sai」だけにする。コミットの「Co-Authored-By: Claude」の行は残す。

### 4.2 公開用に写すスクリプト
- **ファイル**：`C:\senko_program\自作ソフト\portfolio-tools\publish-tumugi.mjs`（公開しないフォルダ）。外部のパッケージは使わない。
- **使い方**：`node publish-tumugi.mjs`。写す元（開発用のリポジトリ）と写す先（`tumugi-public`）は、スクリプトの中に定数で書く。
- **すること**（順番に。どこかで止まったら終了コード1）
  1. 写す元に、コミットしていない変更がない（`git status --porcelain` が空）。あれば止める。
  2. 写す先の中身を、`.git` 以外すべて消す。
  3. 写す元の `HEAD` を `git archive` で取り出し、写す先に展開する。`.gitattributes` で `export-ignore` を付けたものは入らない。
  4. 写す先のファイルを確かめる。
     - forbidden.txt の文字列が、どのファイルにも入っていない。見つかったら、ファイル名と forbidden.txt の行番号だけを出す。
     - `.env` という名前のファイルがない。
     - パスワードなどをそのまま書いた形（`password`・`secret`・`api_key`・`token` に、4文字以上の文字列が `=` か `:` で続くもの）が、Markdown 以外のファイルにない。
     - `.env.example` の `DB_PASS`・`DB_ROOT_PASS`・`DEMO_PASSWORD` が、写す元の `.env` と違う値。値そのものは出さない。
     - 5MB を超えるファイルがない。
  5. すべて通ったら、写す元のコミット（短いハッシュ）と、写す先の `git status --short` の要約を出す。
- **しないこと**：コミットと push はしない。毎回ユーザーに確認してから、手で行う。
- **公開用のコミットのメッセージ**：「公開版を更新した（開発用 <短いハッシュ> の時点）」。最後に Co-Authored-By の行を付ける。

### 4.3 公開しないもの

## 6. リスクと対策
- **これから書く開発ログなどに、本名や秘密情報を書いてしまう**：写すたびにスクリプトが確かめ、見つかったら止める。
- **写すのを忘れて、公開版が古くなる**：セッションの終わりに開発ログを書くとき、公開するかを確かめる。

- **公開すると、GitHub の上で複製（フォーク）はできる**：GitHub の規約で許されていることで、止められない。それ以外の利用は README でお断りする。
