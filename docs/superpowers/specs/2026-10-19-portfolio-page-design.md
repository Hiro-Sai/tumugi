# ポートフォリオの紹介ページ（1段目） 設計書

- 日付：2026-10-19
- 状態：実装済み（2026-10-19、ユーザー確認済み）。`https://hiro-sai.github.io/` で公開した。
  - 実装中に決めたこと：ユーザー名とハンドルネームは「Hiro-Sai」にした。リポジトリ名は小文字の `hiro-sai.github.io`（ユーザー名に大文字があるときの GitHub の決まり）。自己紹介は案 A。

## 1. 背景と目的

### 背景
- 展示（2026-10-17〜）が終わった。就職活動の名刺に、つむぎを URL または QR で載せたい。
- 名刺は1〜2週間以内に必要。
- つむぎは各 PC で AI と声を動かす作りなので、QR を読んだ人がその場で触れるデモは作れない（作るならネットの AI を使うことになり、「ローカル完結」と食い違う）。見せられるのは、動画・画面の写真・説明・コード。
- 名刺の QR を読むのは、ほとんどがスマホを持った人事の人。30秒で「何の作品か」が分かるページが要る。コードは、エンジニア向けの次の段。

### 目的
- 名刺の QR から、スマホで「何の作品か」がすぐ分かるページを開けるようにする。
- URL は何年も変わらないものにする（名刺は刷り直しが大変）。

### 成功基準
- 名刺の QR をスマホ2台で読むと、紹介ページが開く。
- 本名・学校名・メールが、ページにも、HTML のソースにも、Git の履歴（作者名・メール）にも出ない。
- 外部への読み込み（フォント・スクリプト・解析ツール・広告）がない。
- スマホの幅（360px）で、横スクロールが出ない。
- クレジットと断り書きがある。

## 2. 決定事項（ユーザーと合意したもの）

1. QR の行き先は紹介ページ（GitHub Pages）。人事が最初に見て、エンジニアはそこからコードへ進む。
2. コードは公開する。ライセンスは付けず、README に「閲覧用・無断での利用・改変・再配布はお断り」と書く（2段目）。
   - 公開しても著作権はなくならない。ライセンスがなければ、ほかの人はコピー・改変・配布ができない。
3. 公開するコードの履歴は1件にまとめる（2段目）。手元のリポジトリ（42件の履歴）は、そのまま残す。
4. 動画は、これから自分の PC で録る（2段目）。展示の来場者は映さない。
5. ページの置き場所は「ユーザー名.github.io」（自分のページ）。これからの作品も足せるので、名刺を刷り直さなくてよい。
6. GitHub のユーザー名は、公開の前にユーザーが変える。
7. 急ぎなので2段に分ける。1段目（このテーマ）は紹介ページと QR。2段目は動画とコードの公開で、別に設計する。
8. 名前は出さない。ハンドルネーム（GitHub のユーザー名）だけにする。本名・学校名・メールは載せない。

## 4. 設計

### 4.1 URL とリポジトリ
- **URL**：`https://<ユーザー名>.github.io/`（ユーザー名は小文字で書く）
- **GitHub**：公開リポジトリ `<ユーザー名>.github.io` を作り、main ブランチのルートを GitHub Pages で公開する。
- **手元のフォルダ**：`C:\senko_program\自作ソフト\portfolio`。つむぎのリポジトリとは別の Git リポジトリにする。
- **Git の作者**
  - このリポジトリだけの設定（`git config --local`）にする。グローバルの設定は変えない。
  - 名前はハンドルネーム。メールは GitHub の非公開用アドレス（`<ID>+<ユーザー名>@users.noreply.github.com`。GitHub の設定画面に出る）。
- **GitHub の設定**（ユーザーが行う）：Settings → Emails の「Keep my email addresses private」と「Block command line pushes that expose my email」。

### 4.2 ファイル構成
```
portfolio/
├── index.html            … ページ本体。CSS もこの中に書く。JavaScript は使わない
├── images/
│   ├── tumugi-chat.jpg       … 会話の画面
│   └── tumugi-dashboard.jpg  … 管理者のダッシュボード
└── .nojekyll             … GitHub Pages の加工（Jekyll）を止める空のファイル
```
- QR の画像は、このリポジトリに入れない（名刺の入稿用なので、別のフォルダに置く）。

### 4.3 ページの中身（上から順に）
1. **ヘッダー**
   - ハンドルネーム。
   - 一言の自己紹介。文はユーザーが書く。仮の文を入れておき、ユーザーが差し替える。
2. **つむぎの紹介**
   - **見出しと1行の説明**：「共感AIつむぎ」。社員がつむぎと話すと、気持ちが匿名で集計され、会社には組織の傾向だけが見える。
   - **画面の写真**：会話の画面と、管理者のダッシュボード。
   - **動画**：「近日公開」と書き、2段目で差し替える。
   - **どんな作品か**（3〜4行）
     - 社員が話しかけると、つむぎが表情と声で返事をする。
     - 会話から社員の気持ちを6種類に分けて記録する。
     - 管理者は部署ごとの傾向だけを見られて、個人は見えない。
   - **工夫した点**（それぞれ1〜2行）
     1. 会話がネットに出ない：AI（Ollama と Gemma 4）も声（VOICEVOX）も、その PC の中で動く。
     2. 個人を特定させない：直近7日間に記録がある社員が10名未満の部署は、数字を出さない。
     3. 記憶の暗号化：つむぎが覚えた内容は、社員のパスワードから作った鍵で暗号化して保存する。
     4. 見逃しを減らす：危ない話かどうかは、返事を作る AI とは別の呼び出しで判定する。
     5. 声に合わせて口が動く：VOICEVOX の音の長さに合わせて、口を開け閉めする。
   - **使った技術**：Electron、Ollama（Gemma 4）、VOICEVOX、PHP、MySQL、Docker
   - **コード**：「近日公開」と書き、2段目で GitHub へのリンクに差し替える。
   - まだ作っていない機能（本人の申し出で相談担当につなぐ機能など）は書かない。
3. **フッター**
   - クレジット：「VOICEVOX:春日部つむぎ」「立ち絵：坂本アヒル」
   - 断り書き：「春日部つむぎ公式とは関係のない、個人の作品です」
   - 「© 2026 <ハンドルネーム>」

### 4.4 見た目と作り
- **レイアウト**：スマホ優先の1列。最大幅は約720px で、中央に寄せる。
- **文字**：OS に入っている日本語フォント（`system-ui`、Hiragino Sans、Yu Gothic UI、Meiryo の順）。外部のフォントは読み込まない。
- **色**：白い地に、差し色を1つ。ダークモード（`prefers-color-scheme: dark`）にも合わせる。
- **画像**
  - 横幅いっぱいに表示する。`width` と `height` を書き、読み込み中に画面がずれないようにする。`alt` と `loading="lazy"` を付ける。
  - 長辺は1280px 以下の JPEG にし、1枚300KB 程度を目安にする。
- **meta**
  - viewport と description を入れる。
  - SNS やチャットで共有したときの表示（`og:title`・`og:description`・`og:url`・`og:image`）も入れる。`og:image` は会話の画面写真の絶対 URL。
  - 検索エンジンに載ることは止めない（名前が出ないため）。

### 4.5 画面の写真（ユーザーが撮る）
- 展示モード（`npm start -- --exhibit`）で、デモ用の架空の社員（E001 など）にログインする。展示モードなので、記憶は残らない。
- **会話の画面**：2〜3往復したところ。つむぎの返事と表情が見えるところを撮る。会話は作り話にする（自分の本当の悩みは書かない）。
- **ダッシュボード**：A001 でログインし、管理者の画面を撮る。
- **撮り方**
  - アプリのウィンドウだけを撮る（Alt＋PrintScreen、または Win＋Shift＋S のウィンドウ選択）。
  - デスクトップやタスクバー（ユーザー名やファイル名）を映さない。
- **縮め方**：Claude が、つむぎに入っている Electron の画像の機能（nativeImage）を使う使い捨てのスクリプトで、縮めて JPEG にする。新しいものはダウンロードしない。

### 4.6 QR
- **中身**：`https://<ユーザー名>.github.io/` だけ。期限があったり、リダイレクトしたりする QR 作成サービスは使わない。
- **作り方**
  - 誤り訂正はレベル M。印刷用に SVG（拡大しても粗くならない）と PNG を作る。
  - npm の `qrcode` を一時フォルダに入れて作る。どのプロジェクトの依存にも足さない。入れる前にユーザーに確認する。
  - 名刺の印刷サービスに QR を作る機能があれば、それを使ってもよい。その場合も、期限のないもの（静的な QR）かを確かめる。
- **印刷の注意**
  - 一辺2cm 以上にし、周りに白い余白（4マス分）をとる。
  - 黒と白で刷る（色を薄くしない）。
  - QR の横に URL の文字も書く（QR が読めない人のため）。

### 4.7 公開までの流れ
1. **ユーザー**：GitHub のユーザー名を変える。4.1 のメールの設定を2つ入れる。新しいユーザー名を Claude に伝える。
2. **Claude**：portfolio フォルダに `index.html` と `.nojekyll` を作る（完全なファイルで）。
3. **ユーザー**：画面の写真を撮る。**Claude**：写真を縮めて、images に入れる。
4. **ユーザー**：ブラウザで `index.html` を開き、PC の幅とスマホの幅（開発者ツールの端末表示）で確かめる。自己紹介の文を書く。
5. **Claude**：`git init`、作者の設定、コミット（何をコミットするかを見せて、確認してから）。
6. **ユーザー**：GitHub で空の公開リポジトリ `<ユーザー名>.github.io` を作る。
7. **Claude**：リモートを足し、push する（公開になるので、push の前にユーザーに確認する）。サインインの画面が出たら、ユーザーがサインインする。
8. **ユーザー**：Settings → Pages で、main ブランチのルートから公開されているかを確かめる。数分たってから、URL を開く。
9. **Claude**：QR を作る。**ユーザー**：スマホ2台と試し刷りで、読めるかを確かめる。それから名刺を入稿する。

### 4.8 確認の手順（成功基準に対応）
- **開ける**：スマホの実機で URL と QR から開き、表示が崩れない。
- **横スクロールがない**：スマホの幅（360px）で、横スクロールが出ない。
- **外部への読み込みがない**：開発者ツールの Network に、`<ユーザー名>.github.io` 以外への通信がない。
- **名前が出ない**
  - `git log --format='%an <%ae>'` に、ハンドルネームと非公開用のアドレスしか出ない。
  - `index.html` に、本名・学校名・学校のメールの文字列がない。
- **表記**：クレジットと断り書きがある。

## 6. リスクと対策
- **あとでユーザー名を変えると、名刺の QR が開かなくなる**：印刷の前に決め、そのあとは変えない。
- **写真に個人の情報が映る**：ウィンドウだけを撮る。架空の社員と、作り話の会話にする。
- **「近日公開」のまま止まると、作りかけに見える**：2段目を、名刺の印刷を待つ間に進める。
- **立ち絵や声の規約は、予告なく変わることがある**：公開の前と、名刺を刷り直すたびに確かめる。
