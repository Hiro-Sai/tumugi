   - 今までは、Ollama が動いていれば、起動時には何も出なかった。モデルが入っていない PC では、話しかけると「頭真っ白…」と代わりの返事が出るだけで、原因にたどり着けなかった。
   - ユーザーが決めたこと：知らせは、起動時と、話しかけたときの両方で出す（起動時に Ollama が止まっていて、あとから起動した場合も分かるように）。
   - 起動時は、Ollama のモデルの一覧に、使うモデルがあるかを確かめる。話しかけたときは、Ollama が 404（モデルがない）を返したら、「頭真っ白」の代わりに知らせる。
   - 知らせの文：「⚠️ AIのモデル（gemma4:e4b）が入っていないみたい…「ollama pull gemma4:e4b」を実行してから話しかけてね」。入力は止めない。モデルを入れれば、アプリを開き直さなくても話せる。
   - まとめ役が決めたこと：
     - 名前の前のほうが同じというだけでは「ある」にしない。大文字と小文字は区別せず、タグがなければ latest として比べる（Ollama と同じ）。
     - 勧めるのは pull（run だと、入れたあとに端末で会話が始まるため）。
   - D7（Ollama が動いていない・モデルがないときの案内）は、これで「案内だけ」がそろったので、一緒に直したことにした。アプリから Ollama を起動する案は、セッション4で決めたとおり扱わない。
3. **記憶が読めなかったときに、本人に知らせるようにした（レビューの A4）。**
   - 記憶の鍵はパスワードから作るので、管理者が仮のパスワードを発行したときや、ほかの PC でパスワードを変えたときは、前の記憶が読めなくなり、消える（セッション3で決めた設計）。今までは、そのとき画面に何も出ず、「はじめに」の画面がもう一度出るだけだった。
   - ユーザーが決めたこと：知らせは「はじめに」の画面の中に出す（題の下に、青い線で理由の文）。
   - 文：「前の記憶を読めなかったので、もう一度教えてください。パスワードが変わると（管理者が仮のパスワードを発行したときや、ほかの PC で変えたとき）、それまでの記憶は読めなくなります。」ファイルが壊れたときにも当てはまるよう、原因は言い切らない。
   - 読めないときの扱いは、`memory-crypto.js` の `openMemoryRecord` に出して、テストした。
     - 鍵が合わない・壊れているとき：今までどおり消して、知らせる。
     - OS の暗号（safeStorage）を外せないとき：知らせるが、消さない（次に記憶を保存するときに上書きされる）。
4. どちらも小さい直しなので、設計書は作らず、決めたことはこのログに書いた。エージェントは使わず、まとめ役が直して、ユーザーが確かめた。

## 学んだこと

- 外のソフト（Ollama）の答え方は、文書や記憶に頼らず、手元で1回呼んで確かめると早い（404 の返し方、名前の大文字・小文字、タグのない名前）。
- 同じ「読めない」でも、消すか残すかで、知らせが1回で終わるか、毎回出るかが変わる。扱いを1つの関数にまとめると、表のように並べてテストできる。
- 確かめのために一時的に変える行（DevTools）は、そのテーマで同じファイルを変えたときは、ファイルごと戻せない。その行だけを戻して、元と比べる。
