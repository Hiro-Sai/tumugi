## 口パクの方式の比べ（10/16）

VOICEVOX でつむぎの声を4文作り、口の開け閉めを計算で再現した。

| 方式 | 1秒に開く回数 | 開いている割合 |
|---|---|---|
| 声の大きさで決める（数字を6通り試した） | 0.6〜2.8回 | 6〜68% |
| 音ごとの長さで決める（採用） | 3.2〜5.5回 | 39〜50% |

- つむぎの声は音と音のあいだで音量があまり下がらないので、声の大きさでは区切りを拾えない。「あいうえお」の音は1秒に5〜7個ある。
- 音ごとの長さは、VOICEVOX の audio_query にある（子音・母音の長さ、息つぎ、前後の無音）。アプリは声を作るときにもともとこれを受け取っている。

## 決めたこと

- **ユーザーの感情は、返事の呼び出しで決める。**
  - 欄は返事の JSON の先頭に置き、返事を書く前に決めさせる（返事に引っぱられないように）。
  - 判定の呼び出しには触れない。判定の指示は言い回し1つで拾える危機が入れ替わるので、変えるときは必ず測り直す。
- **ユーザーの感情のスコア**：happy 0・normal 10・tired 50・angry 50・anxious 60・sad 70（危機は今どおり100）。落ち込み・自分を責める気持ちを、いちばん危ないサインとして高くした。前の分類（surprised・troubled）のログは DB に残るが、スコアは記録時に保存済みなので集計には響かない。
- **感情ログは、判定と返事の両方が成功したときだけ送る。** 失敗した回を normal などで埋めると、実際にはない記録が混ざるため。危機のときは sad として送る（スコアはサーバー側で100になる）。
- **壊れた返事は1回だけ作り直し**、それでもだめなら代わりの返事にする（感情ログは送らない）。
- **展示モード**
  - 記憶はログイン中だけメモリに置き、ディスクには保存しない。
  - 感情ログ送信の同意は、起動時とログアウトのたびに消す。
  - Ollama のモデルを60分読み込んだままにする（Ollama の既定は5分。来場者の間があくと、最初の返事が10秒ほど遅くなるため）。
  - ふだんの `npm start` では、どれも行わない。
- **起動の自動化**
  - サーバー（Docker）はアプリから起動しない。本番では社内サーバーで動くもので、社員の PC で動かすものではないため。展示用の PC だけ `start-demo.bat` で立ち上げる。
  - Ollama は、インストールするとログイン時に自動で起動するので、アプリでは扱わない。
  - VOICEVOX はアプリが起動する。もともと動いていた VOICEVOX には触らず、アプリが起動したエンジンだけを、アプリを閉じるときに止める。起動中なら最大30秒待ってから「起動していない」と案内する。
- **ログイン時のあいさつ**
  - 朝（5〜10時）「おはよ〜、○○。今日はどんな一日になりそう？」、昼（10〜17時）「○○、おつかれ〜。今日はどう過ごしてる？」、夜（17〜5時）「おかえり〜、○○。今日はどんな一日だった？」。
  - 名前は記憶の「名前」。20字を超える名前は使わない。
  - 同意画面や「はじめまして」が閉じてから出す。管理者画面から戻ったときは出さない（「ログインしたばかり」の印をメインプロセスで持つ）。
  - 会話の流れにも入れる（入れても返事が崩れないことを確かめた）。
- **口パク**
  - 母音の間は開き、子音・ん・っ・息つぎ・声の出ない母音（「です」の「す」など）の間は閉じる。
  - 疑問文の句には、語尾上げの分（約0.15秒）を開いたまま足す。
  - 開いているあいだに挟まる40ミリ秒未満の「閉じ」は、開いたままにする（チカチカ防止）。
  - 画像は2枚の切り替え（ユーザーが「2枚」を選んだ。3枚や母音ごとの口の形は、画像を用意する手間が大きい）。
- **立ち絵の決まり**
  - 表情ごとに3枚：`表情_open.png`（元の絵）・`表情_close.png`（まばたき）・`表情_talk.png`（口だけを元の絵と反対にした絵）。
  - 元の絵で口が閉じているのは normal だけ。ほかの5つは、元の絵が口を開けていて、`_talk` は口を閉じた絵。
  - happy は、にっこり目（^^）の顔にそろえた。青い目の絵は `happy_open_blue.png` として残している（使っていない）。
  - surprised と happy は、元の絵とまばたきの絵が同じ（目がもともと閉じているので、まばたきは見えない）。
- **声に合わせて立ち絵を弾ませる案は採用しない。** 悲しい話のときに弾むと、気持ちを逆なでするため。

## つまずいたこと

- **Ollama の版が 0.40.3 から 0.40.4 に変わっていた。** 前回の測定と比べられないので、今の返事も 0.40.4 で測り直した。自動で更新されていたなら、使用中にネットへ出て更新を確認していることになる（残っている課題）。
- **返事が壊れることがあった。** 「お昼はコンビニのパスタだった」で、`<tool_call|>` を出力の上限まで出し続けたり、質問の欄に `」}<tool_call|>};]from_system_prompt…` が混ざったりした。JSON として読めても、アプリならそのまま画面に出ていた。`parseReply` で特殊トークンを見つけたら使わないようにした。
- **CPU だけの時間が、GPU とほとんど同じに出た。** 設定が効いていないのかと疑ったが、0.40.3 の記録と比べると、出力の速さはもともと CPU と GPU でほぼ同じ（約12〜13トークン/秒）だった。差が大きいのは入力の処理（約49 対 603 トークン/秒）で、返事はキャッシュが効くので差がほとんど出ない。
- **口がもともと動いていなかった。** 声の大きさは計算していたが、受け取る `updateFace(isOpen)` がその値を使っていなかった。立ち絵の open/close も、口ではなく目の開け閉じだった。
- **口パクは、画像ができる前にタイミングを確かめる必要があった。** 目を閉じた絵を `_talk` としてコピーして置き、目の動きでタイミングを確かめた（確かめたあとはコピーを消す）。
- **口パクの計算と実際の音声が、0.15秒ほどずれる文があった。** ずれたのは「？」を含む文だけで、VOICEVOX が疑問文の句の終わりに語尾上げの音を足していた。
- **追加された立ち絵の名前がアプリの期待と違った。** 書き出しで `0000` や ` (1)` が付き、normal が `nomal` になっていた。元のファイルは消えていたので、そのままではアプリに立ち絵が出なかった。名前を直した。
- **happy と troubled の口パク用の絵が、元の絵と目まで違っていた。** ピクセル単位で比べて見つけた。troubled は元の絵を書き出し直し、happy はにっこり目の顔にそろえた。
- **シェルの書き換えで、正規表現のバックスラッシュが消えた。** 書き換えるスクリプトをシェルに渡すと、`\[` や `\s` が消えた。バックスラッシュを含む書き換えは Edit ツールで行う。
- **bat ファイルの日本語。** `chcp 65001` より前の行は、UTF-8 の日本語を正しく読めない。`chcp 65001` を2行目に置き、それより前に日本語を書かないようにした。改行は CRLF にした（.gitattributes でも bat は CRLF）。
- **PowerShell 7 で画像を比べようとしたら、C# のコンパイルが通らなかった**（System.Drawing の参照先が .NET Framework と違う）。Node で PNG を読む短いスクリプトを書いて比べた。

## 残っている課題

- **CPU だけの PC での速さと、8GB の PC での確認。** まだ1回の発言に約28秒かかる（いちばん重いのは判定の呼び出し）。実運用の必須条件（事務用 PC でも動くこと）に直結する。結果しだいで、Ollama を各 PC ではなく社内サーバーで動かす形に変わるかもしれない。
- **Ollama の自動更新。** 自動で更新されていたなら、使用中にネットへ出ている。実運用の前に、自動更新を止める方法を確かめる。
- **ダッシュボードの日ごとの差。** 直近7日間の集計を毎日見られるので、前の日との差から1人分の変化を推測できる可能性が少し残る。実運用の前に、対策が必要か決める。
- **本人が選んだときだけ相談担当につなぐ機能**（前のセッションで決定）。相談担当の登録と、通知の届け方を決める必要がある。
- **「感情の流れに注意」の指示に、ユーザーの感情が引っぱられる可能性。** 実際に使って気になったら、指示の書き方を見直す。
- **インストーラーを作る前に必須**：package.json の build 設定（同梱フォントなど）、存在しない admin-demo.html、Mac 用のアイコン `icon.icns` がない、Electron の更新。
- **トークンの問題**（レビューの次の項目）：ログインの期限のずれ、ログアウトしてもトークンが無効にならない、退職者（is_active）を見ていない。
- **立ち絵の利用規約。** 素材の差分を組み合わせて書き出した立ち絵（口パク用の絵など）を使ってよいか、公開する前に確かめる。
- **展示モードは同意の記録をディスクから消すので、同じ PC でふだんの `npm start` を使うと、次のログインで同意画面がもう一度出る。** 展示用の PC なので受け入れている。
