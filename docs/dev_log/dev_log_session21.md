2. **入力の形が違っても、サーバーが 500 を返さないようにした（レビューの A5）。**

   - まとめ役が決めたこと：
     - 社員IDは、社員の管理と同じく、数で届いたら文字として扱う。パスワードは、文字のときだけ、打ったとおりに使う。
     - 感情ログは、気持ちの値がない・文字でないときも、400 で断る（アプリは、気持ちが分かった回だけ送る）。
     - 想定外の例外は、すべての API で、JSON の 500（「サーバーで予期しないエラーが起きました。…」）で返す。中身は、サーバーのログにだけ残す。

## 気づいたこと

- PHP で、`php -r` にコードを渡して動かすと、`set_exception_handler` で登録した処理が呼ばれなかった。同じコードを、スクリプトとして標準入力から渡すと呼ばれた。例外の処理を確かめるときは、スクリプトで動かす（A5）。
- NFKC で直すと、全角の英数字・ハイフン・アンダーバー・空白は半角になるが、長音の「ー」は変わらない。そのため、「ー」が入った社員IDは、サーバーが形の違いを知らせる（A5）。
- 管理者の画面とサーバーには、「7日」を文に直接書いている所がある（テストはない）。最低人数は、サーバーから受け取っているので、ずれない。直すなら、「7日」もサーバーから受け取る形にするのがよい（C6）。
- Electron 45.2.3 の型の定義で、2つ目の起動の知らせ（`second-instance`）は、準備ができたあと（`ready` のあと）に届くことを確かめた（B11）。
