## 決めたこと

- **ローカル完結は絶対条件。** 使用中はインターネットに出ない。PC の中と社内 LAN の通信はよい。導入時に1回だけソフトやモデルをダウンロードするのと、ソースコードを GitHub に保存するのはよい。
- **本番の構成。** 社内サーバー1台と、各社員の PC。
- **サーバーの待ち受け。** 127.0.0.1 だけ（本番でも社内 LAN まで）。DB は Docker の内部ネットワークに置き、インターネットに出られないようにした。
- **phpMyAdmin。** 必要なときだけ起動する（`--profile tools`）。更新確認とエラー報告はオフにした。
- **秘密情報。** リポジトリのルートの `.env` にだけ置く。Git には含めない。
- **デモデータ。**
  - `DEMO_SEED=true` のときだけ投入する。
  - デモ用ではない社員がいる DB では何もせず、エラーで止める（安全装置）。
- **自動起動。** db と app は `restart: unless-stopped` にした。Docker Desktop を再起動すると自動で起動する。
- **改行コード。** LF に統一した（.bat・.cmd・.ps1 だけ CRLF）。
- **Docker Desktop の AI アシスタント（Gordon）は使わない。** エラーや設定を外部に送るため。

## つまずいたこと

- **PowerShell で mysql に SQL を渡すと ERROR 1064 になる。**
  - 原因：引数の中の `"` が消える。
  - 対策：SQL は標準入力から渡す（`"SQL" | docker compose exec -T db sh -c '...'`）。
- **mysql の結果で日本語が `???` になる。** `--default-character-set=utf8mb4` を付ける。
- **発言しても感情ログが記録されない。**
  - 原因：XAMPP 時代に保存された「同意しない」が残っていた。
  - 対策：アプリの「🔒 プライバシー設定」で同意した。
- **phpMyAdmin が「network ... not found」で起動しない。**
  - 原因：`down -v` で古い phpMyAdmin が片付かず、消えたネットワークを参照していた。
  - 対策：停止と初期化のコマンドに `--profile tools` を付けるようにした。

## 残っている課題

- **移行の細かい改善（任意）**
  - 自動再起動を入れたため、`schema.sql` に誤りがあって DB の初回作成に失敗しても、自動で再起動される。2回目からは初期化されないため、テーブルが足りないまま正常に見えることがある。README に「テーブルがないときは `docker compose logs db` を確認する」と足す。
  - README に自動起動の説明がない。
  - 最終レビューの Minor M1〜M7（phpMyAdmin の事前 pull、`main.js` の古いコメントなど）。
- **実運用の前に必須**
  - 実在の社員を DB に登録する手段がない（今はデモの seed だけ）。
- **ローカル完結の仕上げ**
  - Google Fonts を外部から読み込んでいる。
  - CSP（コンテンツセキュリティポリシー）がない。
  - openExternal に許可リストがない。
  - Ollama・VOICEVOX の中継で、パスを検証していない。
  - Ollama・VOICEVOX の接続先が localhost のまま。
- **社内サーバーに置く前**
  - X-Powered-By と Server ヘッダーを隠す。
  - バインドアドレスと接続先を変数にする。
  - TLS（https 化）。
  - ログの上限を決める。
  - DB ユーザーの権限を絞る。
  - Docker Desktop のライセンスを確認する。
- **公開する前**
  - 立ち絵の利用規約を確認する。
  - クレジット表記を「VOICEVOX:春日部つむぎ」に直す。
  - Git の履歴に残っている旧シードスクリプトを確認する。
- **XAMPP の後片付け**
  - `C:\xampp\htdocs\tumugi_server_bak_20261007`（旧ファイルのバックアップ）を消す時期を決める。
  - XAMPP をアンインストールするかを決める。
  - バックアップが残っている間は、XAMPP の Apache を起動しない。
