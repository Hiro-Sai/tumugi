2. **Ollama の側でも cloud の機能を切る手順を、README に足した（レビューの B12）。**
   - つむぎのアプリは、前から cloud モデルの名前を断っていて、つむぎの会話が外に出る道は、もうふさがっていた。これは、Ollama の側でも cloud を断る2枚目の守り。cloud モデルの名前の付け方が変わって、アプリの確かめをすり抜けても、Ollama が断る。

   - ユーザーが決めたこと：
     - 方法は、公式の FAQ の1つ目の、設定のファイル（`%USERPROFILE%\.ollama\server.json`）に書くもの。環境変数のほうは書かない（どちらか1つで効くため）。
     - 展示用の起動ファイル（`start-demo.bat`）は変えない。設定は1回すれば残り、切れていても、アプリが cloud モデルの名前を断るため。
   - まとめ役が決めたこと：
     - ファイルは `Set-Content … -Encoding ascii` で作る。Windows PowerShell 5.1 で、先頭に BOM が付かないようにするため（付くと、JSON として読めないおそれがある）。書き先を作業用のフォルダに変えて 5.1 で試し、BOM なしで、JSON として読めることを確かめた。
     - すでに設定のファイルがあるときは、上書きせずに、メモ帳で足すように書いた。
     - 「セキュリティ上の前提」の、サインインしないでの項目にも1文足した。
3. **Ollama の自動の更新は、止めずに見送った（レビューの B13）。**
   - 調べると、Ollama のアプリは、起動したときと1時間ごとに、新しい版を確かめていた。この日の朝も、起動のすぐあとに新しい版を見つけ、約2分でダウンロードし、Ollama を閉じて入れ替えていた。入れ替えのあいだ（数分）は、つむぎが返事できない。
   - Ollama のアプリの設定画面には、自動のダウンロードを止めるスイッチがありそうだと分かった（アプリの中の文字から。公式の文書には書いていない）。ただし、切っても、新しい版があるかの確かめの通信は続くと考える。
   - ユーザーが決めたこと：
     - 自動の更新は止めない（セキュリティの直しが早く入るため）。
     - README の「セキュリティ上の前提」に、使っているあいだも更新のために通信すること（会話は送らない）と、止めていない理由と、入れ替えのあいだは返事できないことを書く。
     - 「うまく動かないとき」に、つむぎが「Ollamaが起動していないみたい」「Ollamaに繋がらなかったみたい」と言うときの対処（Ollama を起動する。入れ替えの途中なら少し待つ）を書く。この2つの知らせは、前は載っていなかった。
   - まとめ役の理解：ローカル完結の決まりは、会話の中身を外に出さないためのもの。Ollama 自体の更新の通信は会話を含まないので、決まりの外として扱う（計画でユーザーに伝え、そのまま進めた）。
4. **配る形のビルドの設定を直した（レビューの A9 と、E1 の一部）。**
   - 配るためのビルドの設定（`package.json`）に、ないファイルを指す mac 用の設定と、ないページ（`admin-demo.html`）があった。また、node_modules をビルドから除いていたので、配る形に electron-store とフォントが入らなかった（E1）。
   - mac 用の設定と、mac 用のビルドのスクリプトを消した（つむぎは Windows で使う前提。VOICEVOX の自動起動も Windows だけ）。ないページと、node_modules を除く指定も消した。
   - ユーザーが決めたこと：
     - E1 の node_modules も一緒に直し、ビルドして確かめる。
     - 確かめは、インストーラーではなく、インストーラーなしの形（アプリを展開したフォルダ）で行う。この PC はスマート アプリ コントロールがオンで、署名のないインストーラーや、ビルドで書き換えた exe は、止められる見込みのため。
     - ビルドの対象を確かめるテストを足す。前は、「main.js から読むファイルを足したら、ビルドの対象にも足す」を、人が覚えているだけだった。
   - まとめ役が決めたこと：
     - テストは3つ。ビルドの対象に書いたファイルとアイコンがあること。自作のモジュールが読むファイル（モジュールどうしの読み込みも）・preload・開く HTML の付け忘れがないこと。node_modules を除かず、動いているときに読むパッケージが、配る形に入る依存（dependencies）にあること。
     - exe を書き換えない指定は、確かめのビルドのコマンドにだけ付けた（設定のファイルは変えていない）。
   - 確かめでは、できた exe が Electron の本体とバイトまで同じで、スマート アプリ コントロールに止められずに動いた。中身には、electron-store とフォント（とその LICENSE）が入り、開発用の道具とテストは入っていなかった。
   - インストーラーそのものは、署名をするか、別の PC で確かめる。配るときは、立ち絵を外す必要がある（この PC でビルドすると入る。外さないと、素材の再配布になる）。
5. どれも小さい直しなので、設計書は作らず、決めたことはこのログに書いた。直すたびに、ユーザーが画面で確かめた（A9 はテストも。B13 は、コードを変えていない）。
