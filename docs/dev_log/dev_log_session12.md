## 決めたこと

- **言語の構成は変えない。**
- **レビューの修正の前に、サーバーのテストを作る。**
- **進め方**：作業ごとに、実装するエージェントと、読むだけのレビュー担当のエージェントを分ける。エージェントは、テストも Docker も動かさず、コミットもしない。動かして確かめるのはユーザー。コミットは、ユーザーに確認してから。小さな直しは、まとめ役が行う。
- **テストの決まり**：テストごとに DB を空にする。1つずつ順に動かす。パスワードやトークンは、固定の文字列で書かず、その場で作る。特定のエラーを確かめるときは、ほかの項目は正しい値を送る。行が消えたことは、DB の行でも確かめる。

## つまずいたこと

- **「全部通る」と「守りを確かめている」は別だった。**
  - 作業ごとのレビューでは、どれも「動かすと落ちる点はない」で、実際に全部通った。
  - しかし、仕上げの全体レビューで、「サーバーの守りを1つ消しても、落ちるテストがない」所が5つ見つかった。
  - うち3つは、最低人数のテストのデータが「全員が1人1行」だったため。これだと、人数で数えても、記録の数で数えても、同じ結果になる。1人に2行以上入れて、見分けられるようにした。
  - 1つは、消えたことの確かめが、確かめ方のせいで必ず 0 になっていた。テーブルの行の数そのもので確かめるようにした。
  - レビューでは、「落ちるか」だけでなく、「守りを消したら、どのテストが落ちるか」を聞くと、こういう穴が見つかる。
- **テストの数を、数えずに書いた。**
  - エージェントの報告の数を足して「9個」と伝えたが、実際は8個だった。そのあとは、ファイルを数えてから伝えるようにした。
- **PowerShell の `curl` は、curl ではない。**
  - Windows PowerShell では、`curl` は別のコマンドの別名で、curl の書き方が通らない。手順は `curl.exe` と書く。
