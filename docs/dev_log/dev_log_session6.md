- **パスワード変更**（設計は 2026-10-16 に承認）
  - 今のパスワードを間違えたときは、403 で返す。401 だと、アプリが「ログインが切れた」と見なしてログアウトしてしまう。
  - 試せる回数は、ログインと共通にした（15分に5回）。処理は `includes/login_guard.php` に移して、ログインと共有する。
  - 今のパスワードを、新しいパスワードの決まりより先に確かめる。間違えた回数を必ず数えるため。
  - 文字数は、全角や絵文字も1文字と数える（サーバーは `mb_strlen`、アプリは `Array.from`）。上限は72バイト（bcrypt はそれを超えた分を無視するため）。
  - 変えたら、今のトークン以外を消す（ほかの PC のログインを切る）。パスワードの更新と同じトランザクションで行う。
  - 記憶の鍵の付け替えは、サーバーで変わったあとに行う。逆にすると、サーバーで失敗したときに記憶が読めなくなる。
  - 鍵を作っているあいだにログアウトしたら、付け替えをやめる（前の社員の鍵を残さないため）。
  - 展示モードでは、パスワードの欄を出さない（来場者が共用のアカウントのパスワードを変えられないように）。
  - 「プライバシー設定」を「設定」に改めた。
- **トークンの問題**（設計は 2026-10-20 に承認）
  - 範囲は「3つ＋掃除＋ハッシュ」にした。3つは、ログアウトで無効にする、退職者を止める、期限を SQL で計算する。
  - 期限は、アプリが「残りの秒数」（`expires_in`）を受け取り、ログインした瞬間の PC の時計に足して保存する。比べるのも同じ PC の時計なので、サーバーとの時計のずれが効かない。
  - `logout.php` は `verifyToken()` を使わず、消す行がなくても 200 を返す。トークンを持っている人が自分で無効にするだけなので、確かめる必要がない。
  - ログアウトでは、`logout.php` の返事を待たない。サーバーが止まっていてもすぐログイン画面に移れるほうを選んだ。そのときトークンは期限（24時間）まで残る。
  - ハッシュにはソルトを付けない。トークンは32バイトのランダムな値なので、表引きや総当たりで元に戻せない。
  - 入れ替えると、ログインしている人は全員、一度だけログインし直しになる。展示やデモの前日には入れ替えない。
  - 実装は、作業ごとにエージェントに分けて任せ、作業ごとと最後にまとめてレビューした。テストと動作の確認はユーザーが行った。
- **チャットのログが消える不具合は、ダッシュボードを別のウィンドウで開いて直した**（B）。
  - チャットの画面を作り直さないので、吹き出し・会話の履歴・要約・記憶に入れる前の会話・答えている途中の返事や声が、手を加えずに残る。
  - A（会話の状態を main.js のメモリに預け、戻ったら描き直す）は選ばなかった。答えている途中の返事は消え、状態を足すたびに預け忘れのおそれがあるため。
  - 手軽な sessionStorage も使わない。Chromium がディスクに書くことがあり、会話の中身が暗号化されずに PC に残るおそれがあるため。
  - ダッシュボードはチャットの上にモーダルで重ね、閉じるまでチャットは操作できない（今までと同じ使い方で、裏に隠れて見失わない）。
  - 新しいウィンドウにも、チャットと同じ守り（設定・外への画面移動を止める・新しいウィンドウを開かせない）をかける。`main.js` の `WEB_PREFERENCES` と `hardenWindow()` を2つのウィンドウで共有する。
  - ログアウトのとき（ダッシュボードの中で 401 になったときも）は、ダッシュボードを閉じてからログイン画面に戻す。

  - PowerShell からログインの API を2回送ったが、どちらも「社員IDまたはパスワードが正しくありません」になった。
  - サーバーは正しく動いていた（アプリからはログインできた）。入力が画面に出ないため、打ち間違いか、日本語入力がオンのまま入ったと考えられる。
  - 失敗が回数に数えられ、あと2回で E048 が止まるところだった。DB から E048 の失敗を消して戻した。
  - トークンは、アプリでログアウトとログインをくり返して増やした（ログアウトしてもトークンが消えない、という既知の問題を逆に使った）。
  - 回数の制限があるアカウントで確かめるときは、失敗が数えられることを先に伝え、戻す手順を用意しておく。
- **トークンの問題の確認で、E048 が15分止まった。**
  - 退職者の確認（ログインできないことを見る）とパスワードの打ち間違いで、失敗が5回に達した。
  - DB で `is_active = 1` に戻し、E048 の失敗を消す SQL を1つにまとめて、やり直した。やり直すときは、退職者のログインは1回だけ試すよう先に伝えた。
- **計画の手順に、そのままでは確かめられない所が2つあった**（実行する前に直した）。
