## 決めたこと

- **開発は手元で続け、ときどき公開用に写す。**
  - 開発用のリポジトリと履歴（作者が本名の古いコミットを含む）は変えない。
  - 公開用は別のリポジトリで、作者は Hiro-Sai と GitHub の非公開用アドレス。
- **公開用に写すスクリプト `publish-tumugi.mjs`**（公開しないフォルダ `portfolio-tools` に置く）
  - 写す元にコミットしていない変更があれば止まる。
  - 写す先の名前が `tumugi-public` でないときや、`.git` がないときは、何も消さずに止まる。
  - 写したあと、毎回5つを確かめ、1つでも見つかれば止まる。
    - 本名などの文字列
    - `.env`
    - パスワードなどの直書き
    - `.env.example` の値が本物の `.env` と同じでないか
    - 5MB を超えるファイル
  - コミットと push はしない。毎回、人が確認してから行う。
- **公開する文書は、開発ログと設計書だけ。** 計画は長い手順書なので外した。
- **README に、AI（Claude）を使って開発していることを書いた。** 設計の判断は選択肢を比べて自分で決め、理由を設計書と開発ログに残している、と自分の言葉で先に説明する。
- **動画は YouTube に限定公開で上げ、紹介ページからはリンクにした**（埋め込まない）。
  - 最初は、紹介ページのリポジトリに mp4 で置く予定だった。
  - 録った動画が 171.6MB・2分43秒で、縮めるには ffmpeg を入れる必要があったため、YouTube に切り替えた。
  - ページでは、会話の写真に ▶ を重ねて YouTube へのリンクにした。ページを開いただけでは、YouTube から何も読み込まない。
  - チャンネル名は「Hiro-Sai」にし、本名が出ないことを確かめた。
- **動画は、返事を待つ時間も切らずに、本当の速さのまま見せる。**
- **立ち絵は、まばたき・口パク用も含めてすべて坂本アヒルさんの絵。** ユーザーは、素材の差分を表情ごとに組み合わせて書き出しただけ。
- **パスワード変更**（設計は 2026-10-16 に承認）
  - 今のパスワードを間違えたときは、403 で返す。401 だと、アプリが「ログインが切れた」と見なしてログアウトしてしまう。
  - 試せる回数は、ログインと共通にした（15分に5回）。処理は `includes/login_guard.php` に移して、ログインと共有する。
  - 今のパスワードを、新しいパスワードの決まりより先に確かめる。間違えた回数を必ず数えるため。
  - 文字数は、全角や絵文字も1文字と数える（サーバーは `mb_strlen`、アプリは `Array.from`）。上限は72バイト（bcrypt はそれを超えた分を無視するため）。
  - 変えたら、今のトークン以外を消す（ほかの PC のログインを切る）。パスワードの更新と同じトランザクションで行う。
  - 記憶の鍵の付け替えは、サーバーで変わったあとに行う。逆にすると、サーバーで失敗したときに記憶が読めなくなる。
  - 鍵を作っているあいだにログアウトしたら、付け替えをやめる（前の社員の鍵を残さないため）。
  - 展示モードでは、パスワードの欄を出さない（来場者が共用のアカウントのパスワードを変えられないように）。
  - 「プライバシー設定」を「設定」に改めた。

## つまずいたこと

- **立ち絵を「作者が描き足した」と誤って書き、公開したあとで気づいた。**
  - README・開発ログ・設計書の7か所に、同じ誤りがあった。ユーザーの指摘で直し、公開版にも写した。
  - 原因は、前のセッションの開発ログにあった「描き直し」という書き方を、確かめないまま引き継いだこと。
  - 人の作品に関わる書き方は、本人に確かめてから書く。
  - 公開用のリポジトリの最初のコミットには、訂正前の文が残っている。訂正が次のコミットとしてはっきり残っているので、そのままにした。
- **Xbox Game Bar の録画が大きかった。** 画面がほとんど動かなくても毎秒8.8Mbit で記録するため、2分43秒で171.6MB になった（GitHub は100MB を超えるファイルを受け付けない）。
- **`.gitattributes` のフォルダの書き方。** `docs/superpowers/plans/` のように末尾に `/` を付ける書き方は効かない。`docs/superpowers/plans` と `docs/superpowers/plans/**` の2行にした。
- **写すスクリプトの集計の誤り。** 変化の件数を数えるとき、ファイル名に入っている「D」（README の D など）まで「消した」と数えていた。最初に動かす前に、状態を表す先頭2文字だけを見るように直した。
- **パスワード変更の確認で、トークンを増やすのに失敗した。**
  - PowerShell からログインの API を2回送ったが、どちらも「社員IDまたはパスワードが正しくありません」になった。
  - サーバーは正しく動いていた（アプリからはログインできた）。入力が画面に出ないため、打ち間違いか、日本語入力がオンのまま入ったと考えられる。
  - 失敗が回数に数えられ、あと2回で E048 が止まるところだった。DB から E048 の失敗を消して戻した。
  - トークンは、アプリでログアウトとログインをくり返して増やした（ログアウトしてもトークンが消えない、という既知の問題を逆に使った）。
  - 回数の制限があるアカウントで確かめるときは、失敗が数えられることを先に伝え、戻す手順を用意しておく。
