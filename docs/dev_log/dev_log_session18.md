3. **API を、ほかのウェブページから使えないようにした（レビューの B2）。**
   - サーバーは、どのウェブページにも API の結果を読ませる設定（CORS の許し）を返していた。アプリは、画面からではなく main プロセスから送るので、この設定は要らない。
   - CORS の許しを返さないようにした。あわせて、Content-Type が `application/json` でない POST は、DB に触れる前に 415 で断るようにした。ブラウザは、`text/plain` などの POST なら、サーバーの許しがなくても送れるため。
   - 断るのは、本文を読む API だけでなく、すべての POST にした（新しい API で付け忘れないように）。
   - 関数の名前も、`setCorsHeaders` から `startApi` に変えた（CORS を出さないのに、名前が誤解を招くため）。

- 改行コード（CRLF）の確かめに `git diff` を使ったら、CR が見えなかった（Git が、差分を見せるときに落とすため）。ファイルを直接数えて確かめた。

## 学んだこと

- 外のソフトが黙って削るときは、エラーにならないので、実際に送って測らないと分からない。見立てより重いことがある（A2）。
- 新しい class 名を付ける前に、CSS に同じ名前がないか調べる。名前がぶつかると、思わぬ所の見た目が変わる。
- 応答の速さの違いは、何回か測った中央値の比で確かめると、ゆれに強いテストになる（B6）。
- 「見られない」と約束する文は、画面だけでなく、DB を直接扱える人まで考えて書く（B8）。
