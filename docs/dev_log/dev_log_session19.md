2. **パスワードの決まりは、変えずに見送った（レビューの B5）。**
   - まとめ役は、決まりを厳しくする（長くする）ことを勧め、ユーザーも一度はそれを選んだ。そのあとユーザーが、「外に出ないのに、そこまで要る？長いと使う気持ちが下がる」と問い直した。

3. **使っていないコードを消し、モデル名を1か所だけで決めるようにした（レビューの C1）。**
   - script.js に、画面の部品がなく、どこからも呼ばれていない関数があった（モデルの切り替え、キャラ設定の一覧の作成・保存・複製・削除など）。その中には、Electron では使わない決まりの `confirm()` も2か所あった。これらを消し、保存したキャラ設定を読むしくみも消した。返事の指示は、いつも既定の文を使う（文は変えていない）。script.js は 2220行から 1965行になった。
   - モデル名は、前は、PC に保存した名前（localStorage）があれば、それを先に使っていた。書き換える画面がないので、古い名前が残ると、それを使い続けてしまう。
   - ユーザーが決めたこと：モデル名は `js/ollama.js` の `DEFAULT_MODEL` だけで決め、保存した値は読まない。変えたいときの入れ物は、設定ファイル（レビューの D8）で作る。
   - まとめ役が決めたこと：古いキー3つ（モデル名とキャラ設定）は、チャットの画面を開くときに消す（前からある、古いキーを消すしくみに足した）。
4. **ログインのあと、声の準備を待たずに会話を始めるようにした（レビューの A7）。**
   - アプリは、起動するときに VOICEVOX の音声エンジンを立ち上げる。準備には、ふつう10〜20秒かかる。前は、そのあいだにログインすると、準備ができるまで（最大30秒ほど）、チャットの画面は入力を押せず、あいさつも同意画面も出なかった。画面が止まって見えた。
   - ユーザーが決めたこと：
     - 待たずに始める。準備ができるまでの返事は、文字だけにする。
     - 準備ができる前に文字だけで出たあいさつは、準備ができたときに、まだ何も送っていなければ、声で読む。
     - 準備のあいだは、左の状態の所に「声は準備中です」と出す。
   - まとめ役が決めたこと：
     - 準備のあいだは、VOICEVOX に声を頼まず、「声が出せないみたい」とも知らせない。
     - 「声は準備中です」は、状態の表示と同じ行に足すと、左の欄の幅に入りきらず折れるので、その下の行に小さな字で出す。
     - 「Ollama と VOICEVOX が両方起動していない」の知らせは、Ollama の知らせと VOICEVOX の知らせの2つに分けた（VOICEVOX は、待たずに、あとで分かるため）。つむぎの発言の中の ⚠️ は、7か所から6か所になった。
     - 起動のときに「起動できなかった」と知らせたあとは、返事のたびの「声が出せないみたい」を重ねて出さない（前は、VOICEVOX が入っていない PC で、2つ続けて出ていた）。
     - main.js は変えていない。
5. **再生に失敗したときも、作った声のメモリを放すようにした（レビューの A10）。**

## 気づいたこと

- 声の待ちが短いわけ（ユーザーの質問への答え）：返事を最大3つの短い文に分け、1つ目を読んでいるあいだに、次の文の声を作る（文の間は150ミリ秒）。音声エンジンは同じ PC で、アプリの起動のときに立ち上げて、動かしたままにしている。声はファイルに書かず、メモリのまま再生する。ただし、声を作る時間は測っていない。声は、返事の全文がそろってから作り始める。
